## The Starting & Problems

So i was using [OpenClaw](https://github.com/openclaw/openclaw) on my VPS for a while and i setup couple of workflows like -

1.  Set Automated Punch out reminder based on my punch in time in [TickTick](https://ticktick.com)
2.  Generate notes from Meeting Transcript
3.  Manage my schedule based on my current schedule

And a couple more use cases. But I hit the wall of limits soon. OpenClaw is really bad with context after a point.

Every time you start a fresh session, OpenClaw attaches most of the .MD files it made, personality, memory, tools, and a lot.

And that degrades the quality over time as the more it grows, the more bad the context starts to get.

For example, I said.

````
================
    Expected
================

Me: Punch In
OpenClaw: Punch Out at 5:00 P.M.
(should get my current IST time at Punch In time and set punch out after 8h 5m. In Ticktick)

================
    Actual
================

Me: Punch In
OpenClaw: Punch Out at 5:00 P.M. 
(Used UTC time and set a cron instead in fresh session)
````

![OpenClaw Punch-in Error](/blog/imported/how-i-automated-everything-using-ai/openclaw-punchin-error.png)

This is one of the smallest skills I created, and it messes it up every time. And the other thing was OpenClaw was not that secure, even if you added a firewall. Only one person can message and run inside Docker. But no GuardRails for AI to stop.

So i move to different ai quickly which was [Hermes](https://github.com/nousresearch/hermes-agent). It's a **self-improving** AI agent that grows over time. And it has an in-built guardrail setup. Every sensitive command needs your approval. You can choose to

1.  Allow once
2.  Allow in the session
3.  Allow every time
4.  Deny

And this is what I wanted. Hermes by default has a simple context system. SOUL.md, personality, & Tools for context, and every tool has its context.

![Hermes context and tool architecture](/blog/imported/how-i-automated-everything-using-ai/diagram-1.svg)

### Software

How i actually set it up -

1.  Firewall to drop all incoming requests.
2.  ACCEPT TCP PORT 22
3.  Created a new non Sudo user named `hermes`
4.  Installed Hermes using the below command

````
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
````

The Hermes will be installed at `~/.hermes`

Now in Hermes Setup i used

1.  Telegram as messaging gateway.

## The Daily Workflow

Let's talk about some of my workflows and how it works.

### The Daily GYM cron

#### Step 1: Ask the user for sleep + mood, get yesterday's nutrition

-   Ask the user: "How did you sleep? How are you feeling?"
-   Wait for the user's reply (NEVER auto-create)
-   Pull yesterday's log from TickTick (Body & Health) to get nutrition data
-   Use tesseract CLI for the user's diet, steps/activity & sleep screenshots (not vision\_analyze)

#### Step 2: Get the weekly review from second brain

-   Read the most recent weekly review from ~/work/second-brain/03\_Projects/Fitness/
-   This gives the coach context about what's lagging, what to prioritize, what to drop

#### Step 3: Pull last 2-3 same-day sessions + gym equipment list

-   Determine today's split day (Day 1-5 rotation)
-   Find the last 2-3 sessions of the same split from TickTick logs
-   Get the gym equipment list from TickTick (Body & Health, "Gym Equipment Based on Floors")
-   This gives progressive overload context and ensures equipment matches available machines

#### Step 4: Send to Claude opus for exercise selection

-   Draft a prompt with all gathered context (sleep, mood, nutrition, last sessions, weekly review, equipment)
-   Run: claude -p "$(cat /tmp/claude\_workout\_prompt. Txt)" --model opus --max-turns 15 --output-format json
-   Pipe through python 3 to extract .result field, save to /tmp/todays\_workout. Txt
-   Claude handles: exercise selection, weight/reps, progressive overload decisions, what to skip on bad days
-   Claude does NOT handle: log formatting, TickTick operations, talking to the user

#### Step 5: Compile everything and create the log

-   Use Claude's output as the workout plan
-   Add recovery snapshot (sleep from the user's input + screenshots)
-   Add coach call (brief, 2-3 lines)
-   Create the log in TickTick as a note in Body & Health
-   Chat to the user: workout created + brief coach call + 1-2 line yesterday summary
-   Do NOT dump the full workout in chat

![Automated exercise logging workflow](/blog/imported/how-i-automated-everything-using-ai/diagram-2.svg)

#### Exercise Format Template (for TickTick log)

Every exercise in the log MUST use this format:

Plate-Loaded Chest Press (← Exercise name)

Expected (1 plate = 5 kg):

-   Set 1: 2 plates x 12
-   Set 2: 2 plates x 10
-   Set 3: 2 plates x 10

Actual:

-   Set 1: \_\_ plates x \_\_ reps
    
-   Set 2: \_\_ plates x \_\_ reps
    
-   Set 3: \_\_ plates x \_\_ reps
    
-   "Expected" comes from Claude opus output (the target for today)
    
-   "Actual" is filled in later by the user when he completes the workout
    
-   For DB exercises use kg directly (e.g. "7.5 kg x 12")
    
-   For machine exercises use plates (note plate-to-kg conversion if needed)
    
-   Leave Actual as \_\_ blanks until the user reports back
    

#### Rules

-   Each log = THAT DAY's data only
-   Never auto-create without the user's reply
-   Never write the full workout in chat
-   Read gym equipment list before creating workout (pick correct floor/machines)
-   Use tesseract CLI for screenshots (not vision\_analyze)
-   Always read current content before updating
-   Real numbers only, no blanks or placeholders

#### Claude Opus Prompt Template

The prompt should include:

1.  Today's context (day, split, sleep, mood, yesterday's nutrition)
2.  Last 2-3 same-day session data (actual weights/reps)
3.  Key findings from the most recent weekly review
4.  Gym equipment by floor (hard constraint)
5.  Rules (avoid face pulls, deadlifts; time cap 40-45 min; 3 working sets; group by floor)
6.  Output format (exercise name + sets, no markdown, brief notes on notable changes)

### The Punch in out skill

I just told Hermes to create a skill named `punch-in-out`

When i say punch in do the following

-   "Punch in" -> create "Punch out" task in office project in tickitck
-   Use TickTick CLI
-   Use `ist CLI` to get current IST time (not TZ= date)
-   Due date = punch-in time + 8 h 5 m
-   Reminder flag: --reminder "HH: MM" (absolute IST time, 5 min before due)
-   Always confirm actual time with the user before creating

### The Night Cron

At night 9:30 P.M. the following happens:

-   Asks the user for calories, fat, protein and steps walked then updates today's log in TickTick
    
-   Read ticktick. Md and this file before writing to any log.
    
-   Use skill: `ticktick-daily-log` for logging workflow
    
-   Use codex exec for ALL image parsing:
    
    -   Command: `codex exec -m gpt-5.4-mini -i <image_path> --sandbox read-only "Extract ALL nutrition and activity data from this fitness app screenshot. Return calories eaten, remaining, goal, burned, and macros (carbs, fat, protein) with consumed and target values."`
-   Do NOT use _tesseract, vision\_analyze, or browser\_vision_
    
-   The calorie tracking app layout has: Base Goal, Food (consumed), Remaining, Exercise.
    
-   OCR can misalign these numbers. ALWAYS verify with math:
    
    -   Base Goal - Food Consumed = Remaining
    -   If numbers don't add up, re-run codex with a more specific prompt
    -   Do NOT guess or assume which number is which
    -   Verify with the equation
